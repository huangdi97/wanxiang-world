## Objective
Reduce duplicate runtime registries and global lookup mechanisms; keep the two
core registry responsibilities (PackageRegistry and runtime snapshot port) and
remove the one duplicate snapshot-store implementation.

## Delivered
- Merged the duplicate recovery snapshot store: `wanxiang_substrate.recovery.checkpoint`
  no longer implements its own `SnapshotStore` Protocol + `InMemorySnapshotStore`
  (its own `dict[str, InMemoryCanonicalState]` state storage). It now exposes
  `CheckpointStore`, a thin adapter over the single production owner
  `wanxiang_runtime.snapshot.SnapshotStore` port. Recovery keeps only the small
  recovery-specific indexes (latest-per-instance, snapshot-id -> location).
  - `InMemorySnapshotStore = CheckpointStore` deprecated alias kept (API compat).
  - Removed the recovery-local `SnapshotStore` Protocol (no consumers outside the
    module; `ports` count 23 -> 22, `store_classes` 16 -> 15).
  - `CheckpointService` public API unchanged (`save`/`restore` semantics identical).
- Updated `reports/V5_1_DUPLICATE_FORENSICS.md` (regenerated by scanner).
- Added 2 tests: adapter semantics (latest per instance, load by snapshot id,
  NoSnapshot on missing) and deprecated-alias compatibility.
