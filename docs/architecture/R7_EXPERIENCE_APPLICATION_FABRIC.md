# R7 Experience, Projection and Distribution Fabric

## Separation

```text
World != Experience != Projection != Distribution
```

World owns canonical history. Experience defines entry/interaction. Projection
renders committed reality. Distribution packages an experience for a channel.
None above World authority gets a second canonical state.

## ExperienceBlueprint

Defines world ref, interaction/projection refs, experience type, entry mode,
scenario, continuation, zh-CN default locale, sharing/derivative policy,
distribution refs and quality metrics.

## InteractionProfile

Defines input models, allowed action vocabulary and whether interaction is
proposal-only or resolved through world authority.

## ProjectionProfile

Defines provider ref, display capabilities, visible fields, canonical read-model
or committed-StateDiff source and fallback. `write_authority` is fixed to
`none`.

## DistributionAdapter

Defines channel, input/auth/storage/sharing/content policy, capability matrix,
asset/latency/telemetry/update constraints and rights restrictions. Distribution
storage is limited to none/cache/local preferences and cannot be canonical state.

## Shared reality proof

The R7 Original/Fiction slice composes a player/roleplay Experience and a
read-only observer/research Experience over the same WorldRuntime. Player commits
immediately change the observer view because both derive from the same committed
worldline. Branching creates another worldline, not an Experience-owned copy.

## Product continuity

The existing M95-R player path remains zh-CN-first, Player/Studio separated, and
Leave->Continue preserves the same committed worldline/actor state. Contract
vocabulary such as Steam/VR is not called a shipped product without adapter and
application evidence.
